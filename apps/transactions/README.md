# Веб-сервис для учёта движения денежных средств (ДДС)

## Описание

Веб-приложение для ведения учёта денежных операций с возможностью создания, редактирования, удаления и просмотра записей. Поддерживает иерархические справочники: статусы, типы, категории и подкатегории с логическими зависимостями. Реализована фильтрация записей по дате, статусу, типу, категории и подкатегории.

## Технологии

- **Backend**: Python 3.11, Django 4.2
- **База данных**: PostgreSQL 15
- **Frontend**: Bootstrap 5, JavaScript (динамическая фильтрация форм)
- **Контейнеризация**: Docker, Docker Compose

### Локальный запуск (без Docker)
1. Создайте и активируйте виртуальное окружение:

bash
python -m venv venv
source venv/bin/activate  # или venv\Scripts\activate на Windows

2. Установите зависимости:

bash
pip install -r requirements.txt

3. Настройте базу данных PostgreSQL (создайте базу cashflow и пользователя postgres с паролем postgres или измените параметры в cashflow/settings.py).

4. Примените миграции:

bash
python manage.py migrate

5. Создайте суперпользователя:

bash
python manage.py createsuperuser

6. Запустите сервер разработки:

bash
python manage.py runserver

### Использование
## Основные страницы

Главная (/) – список записей ДДС с возможностью фильтрации по дате, статусу, типу, категории, подкатегории.

Создание записи (/create/) – форма с полями: дата, статус, тип, категория, подкатегория, сумма, комментарий.

Редактирование записи (/<id>/edit/) – аналогично созданию.

Удаление записи (/<id>/delete/) – подтверждение удаления.

Справочники – управление статусами, типами, категориями, подкатегориями через выпадающее меню «Справочники».

## Фильтрация записей

На главной странице доступны фильтры:

Дата с / Дата по

Статус (выпадающий список)

Тип (выпадающий список)

Категория (выпадающий список)

Подкатегория (выпадающий список)

После выбора значений нажмите «Применить фильтры». Сброс фильтров – кнопка «Сбросить».

## Управление справочниками
Статусы – названия (например, Бизнес, Личное, Налог).

Типы – Пополнение, Списание (список может расширяться).

Категории – привязаны к типу. Пример: тип «Списание» → категория «Маркетинг».

Подкатегории – привязаны к категории. Пример: категория «Маркетинг» → подкатегории «Farpost», «Avito».

Добавление, редактирование и удаление элементов справочника происходит через отдельные страницы (доступны по ссылкам в меню «Справочники»).

## Административная панель

По адресу /admin доступна стандартная админка Django. Здесь также можно управлять всеми моделями.

## API для динамических форм

Для динамической фильтрации категорий и подкатегорий в формах используются два эндпоинта:

GET /api/categories/?type=<id> – возвращает JSON-список категорий для выбранного типа.

GET /api/subcategories/?category=<id> – возвращает JSON-список подкатегорий для выбранной категории.

Эти эндпоинты вызываются через JavaScript в формах создания/редактирования записей и справочников.

## Бизнес-правила

Подкатегория всегда должна соответствовать выбранной категории (проверка на стороне сервера в TransactionForm.clean()).

При удалении категории каскадно удаляются связанные подкатегории (в моделях Category и Subcategory используется on_delete=models.CASCADE).

При удалении типа каскадно удаляются связанные категории (а через них и подкатегории).

При попытке удалить статус, тип, категорию или подкатегорию, на которые есть ссылки в записях, сработает защита (on_delete=models.PROTECT), и Django вернёт ошибку (сообщение пользователю).

## Структура базы данных

Основные таблицы:

transactions_status – статусы (Бизнес, Личное, Налог)

transactions_type – типы (Пополнение, Списание)

transactions_category – категории (связь с типом)

transactions_subcategory – подкатегории (связь с категорией)

transactions_transaction – записи ДДС (связи с вышеуказанными справочниками)

Все первичные ключи – BigAutoField.

## Возможные проблемы и их решение

Ошибка TemplateDoesNotExist – проверьте, что файлы шаблонов названы точно как в views.py и лежат в правильных папках. base.html должен быть в templates/, а остальные – в templates/transactions/.

Ошибка подключения к PostgreSQL – убедитесь, что контейнер db запущен, а в settings.py указан HOST: db (для Docker) или localhost (для локального запуска).

Нет миграций – выполните python manage.py makemigrations и python manage.py migrate. Если приложение не создаёт миграции, проверьте, что оно добавлено в INSTALLED_APPS как 'apps.transactions'.

404 при переходе на справочники – убедитесь, что в apps/transactions/urls.py есть все маршруты, описанные в README.

## Разработка и расширение

Для добавления новых полей в модель транзакции или справочники – измените соответствующие модели, создайте миграцию, обновите формы и шаблоны.

Для изменения логики фильтрации – отредактируйте transaction_list в views.py и шаблон transaction_list.html.

Для изменения внешнего вида – отредактируйте base.html и файлы в папке templates/transactions/.
